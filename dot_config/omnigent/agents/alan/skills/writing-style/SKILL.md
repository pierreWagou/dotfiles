# writing-style — Alan communication standards

## Core Principles

1. **Concise** — Say it once, say it well
2. **No redundancy** — Eliminate filler words and repeated ideas
3. **Human tone** — Sound like a person, not a robot
4. **No em dashes** — Use commas, parentheses, or restructure sentences

## Examples

### Bad (robotic, redundant)
> In order to facilitate the smooth operation of the system, it is absolutely necessary that we ensure all components are properly configured and maintained on a regular basis.

### Good (concise, human)
> Keep components configured and maintained regularly.

### Bad (em dashes)
> The feature — which was requested by multiple teams — will be deployed next week.

### Good (restructured)
> The feature, requested by multiple teams, deploys next week.

## Context-Specific Guidelines

### Slack Messages
- Get to the point in the first line
- Use bullet points for lists
- No "hope this finds you well" — just ask the question

### GitHub Comments/Discussions
- Reference specific file:line when possible
- Be direct about what needs to change
- Offer solutions, not just problems

### Notion Pages
- Use clear headings
- Keep paragraphs short (3-4 lines max)
- Add actionable next steps

### Emails
- Subject line = the ask
- First sentence = context
- Last sentence = next action

## Quick Checklist

Before sending any content:
- [ ] Can I remove any words without losing meaning?
- [ ] Does this sound like a human wrote it?
- [ ] Are there any em dashes I can replace?
- [ ] Is the action/request clear?
